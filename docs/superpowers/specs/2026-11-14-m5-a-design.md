# M5-A 디자인 테마 구현 설계

## 목적과 범위

`CODEX_TASK_M5.md`의 A를 구현한다. 로컬 단일 사용자 도구에서 같은 draft를 classic/minimal/bold로 미리보고 선택한 테마로 승인·ZIP 다운로드한다. B~D는 A의 전체 테스트·커밋·푸시 후 순서대로 진행한다. 배포·크롤링·로그인·유료 API는 추가하지 않는다.

## 구현 방식과 대안

지시서가 정한 공유 섹션 HTML + 테마 CSS·토큰 방식을 채택한다. 테마별 HTML 복제는 공유 구조 요구에 맞지 않고, CSS 문자열을 UI에 직접 넣는 방식은 core 공용 로직 요구에 맞지 않는다. 기존 `core/render.py`를 중심으로 연결하는 것이 현재 구조에 맞는 방식이다. 구현 세부 선택은 아래와 같이 제안한다.

## 테마와 검증

`core/themes.py`에서 테마 id 허용 목록, TOML 토큰 스키마, CSS 검증과 색 계산을 담당한다. `themes/<id>/theme.toml`은 이름·설명과 색상·여백·글자 크기 비율·모서리 토큰을 담고 `theme.css`는 공유 섹션 선택자를 사용한다. 임의 경로와 알 수 없는 id, 누락·잘못된 토큰, 외부 URL·프로토콜 상대 URL·@import는 거부한다. 기존 로컬 폰트만 쓴다.

classic은 기존 CSS의 배치·치수와 기존 샘플의 색을 유지한다. minimal은 흰 배경·넓은 여백·얇은 선, bold는 큰 브랜드 배경·큰 제목·교차 배경을 사용한다. 토큰은 CSS에 안전한 검증된 값으로만 전달한다.

## 대비와 호환성

core의 sRGB 상대 휘도 계산으로 본문 4.5:1, 큰 제목 3:1을 검증한다. 브랜드 배경 위에는 기준을 만족하는 검정 또는 흰색을 고르고, 밝은 배경의 브랜드 글자는 필요한 경우 어둡게 보정한다. 실제 사용하는 전경·배경 쌍을 검사하고 충족 실패만 검수 항목에 남긴다. 성공한 보정은 검수 항목이 아니며 원래 값·보정 값·보정 전후 대비 비율을 manifest의 `contrast_adjustments`에 저장하고 미리보기에 "브랜드 색 대비 보정됨"을 표시한다. 원본 상품 브랜드 색과 문구는 수정하지 않는다.

기존 샘플과 기준을 이미 만족하는 classic 색 조합은 기존 렌더링을 유지한다. 대비가 부족한 입력은 읽기 쉬움을 우선해 파생 글자색을 보정하므로 해당 입력의 픽셀은 이전과 달라질 수 있다. 이 예외는 사용자가 승인했다. 기존 샘플 #305b46 및 기준을 충족하는 색은 픽셀 단위로 유지한다. 이 예외를 테스트와 README에 명시한다.

## 작업 상태·화면·CLI

새 필드가 없는 기존 작업은 classic으로 읽는다. 작업 및 렌더링 manifest에 theme id를 저장하고 ZIP은 해당 불변 스냅샷의 manifest와 CSS를 포함한다. 테마 id를 렌더링 재사용 조건에 포함한다. ⑤에서 테마를 바꾸면 새 스냅샷을 만들며 이전 폴더를 보존한다. 승인과 다운로드는 선택한 테마의 스냅샷을 사용하고 테마 변경 시 이전 승인 체크 상태를 재사용하지 않는다.

`render`, `preview_job`, `ingest_job`, `generate_job`, `accept_job`과 호출부를 함께 확장한다. CLI의 M1 `--input`, ingest, generate, accept에 `--theme`를 추가한다. 생략 시 기존 작업의 설정을 유지하고 설정도 없으면 classic이다.

## 검증과 결과물

변경 전 기준 전체 테스트와 변경 후 전체 테스트를 실행한다. 테마·대비·안전성·하위 호환 단위 테스트, 세 테마 실제 Chromium 렌더링(폭 860·넘침 없음·한글 폰트), classic 기준 비교, AppTest의 테마 변경·스냅샷 보존·ZIP 기록을 검증한다. 테스트는 임시 폴더만 쓴다. 테마 캡처는 `tools/make_screenshots.py`를 명시 실행해 만든다. README를 갱신하고 작업 A만 지정 브랜치에 커밋·푸시한 뒤 지시서의 다섯 항목으로 보고한다.
